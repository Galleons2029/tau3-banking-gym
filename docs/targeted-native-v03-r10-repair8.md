# r10 repair8：公开账户义务、用户结束条件与原文保留

## 原阻塞与修复

repair7 最终有 388/400 个有效正式任务、1550/1600 个完整采样槽位及 199/200 个验证任务。
2026-09-20 对剩余证据逐项检查后，确认以下四类原因：

1. 10 个账户关闭任务中的目标账户没有关联借记卡。审核器把“关闭所有关联卡”误读成
   必须存在并关闭至少一张卡。新增私有准入证据通过真实公开工具列出账户与关联卡，
   验证业务状态不变。空集合不需要写入；若实际存在未纳入参考动作和独立目标的卡则拒绝。
2. 2 个信用卡销户任务没有明确指定还款账户与信用卡的对应关系。这是数据歧义，现为
   各还款账户设置公开可查询的唯一昵称，并向用户提供卡尾号与昵称映射。独立检查器
   验证客户归属、唯一性和实际参考扣款账户一致，错误映射必须被拒绝。
3. 正式任务 238 的两个未完整槽位中，用户模拟器在实际转接成功后仍反复要求真人进入
   当前聊天，导致长度或时间耗尽。修正所有事故升级场景的用户规则：收到明确已完成的
   转接通知后结束；仅计划转接或转接失败时继续要求处理。实际转接动作与正确 reason
   仍由独立评分器要求，错误 reason 不会因用户结束而成为成功。
4. 验证任务 31 的自然语言改写反复改变用户选择范围。对结构正确但等价性审核失败的
   改写，保留原始客户请求，并保存原负面审核、拒绝文本、原文哈希与恒等证明。双模型
   的公开可解性和信息泄漏审核仍需通过；格式错误的审核仍属于未决。

业务分组、参考动作长度、配额、四个固定 seed、200 步和 3600 秒预算均未改变。
GLM 与 Gemini 共用请求池上限 256。教师使用 GLM，用户和质量审核使用 Gemini。

新旧 3220 个候选实例逐项对照：试跑 1 题、全部训练计划 255 题发生变化，其中正式前
400 题占 34 题。变化任务重新采满四次；未变化任务仅在证书、配置、业务状态、原始
捕获和严格回放均匹配时复用，原失败不被选择性替换。验证任务业务内容未改变。
