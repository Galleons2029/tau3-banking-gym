# 角色审核后的真实 3000 轨迹生产

## 目标与运行

用户授权继续生产至少 3000 条真实、不同且审核合格的教师轨迹。新轮目录：`data/synthesis/targeted-native-v03-r10-expand3k-v2`。后台 supervisor PID 455548，独立捕获审计 observer PID 459199。启动不代表 3000 条已完成，当前阶段以 `supervisor.json` 和 `verification/progress.py` 为准。

旧 expand3k-v1 完成 800/800 个有效任务准入且请求全部结算后，关闭暂停的旧 supervisor；没有取消在途采样，没有放行旧教师阶段。新版本继承累计 110279 次物理调用、1900 个教师采样槽位及所有累计 token 和 blind 预算。

## 历史样本与新增轨迹

- 原正式集 890 条中，765 条通过独立角色复审，114 条舍弃，11 条隔离；新交付至少还需新增 2235 条。
- `retained-sft-binding.json` 冻结清理 manifest、原文件与逐行审核索引的哈希。交付检查要求全部保留行仍在，全部排除行不在；不再要求纳入旧的全部 890 条。
- 复用旧任务原有四个采样槽位，包括失败记录。若直接父轮只有准入任务而没有教师采样，沿已结算的预算祖先链定位原始捕获；严格重放并重新绑定证据，不重新抽取旧 seed。
- 复用历史审核时要求用户对话上下文哈希一致、两模型完整通过、真实捕获已经严格重放。历史用户提示词如实保留为历史证据，不伪装成新提示词采样。

## 新采样与质量门禁

新用户请求使用 `customer_role_v2`，即简短的客户角色约束。对照实验表明它仍不能消除串角色，因此每条候选 SFT 必须通过 GLM 与 Gemini 的独立逐用户回合审核，以及原有环境成功、推理质量、协议与 token 检查。用户行为不合格整条拒绝，不改写用户话术后拼接原教师回复。

教师 GLM-5.3-Flash，用户 Gemini-3.5-Flash；模型配置、四个固定 seed、200 步上限、3600 秒轨迹时限保持原配置。所有角色审核和重试进入累计预算。新模型物理请求共用 256 并发池。

每次导出再核对 SFT 行的角色审核哈希、结果哈希、模型身份和 KEEP 判定，独立 observer 检查原始捕获、工具配对与真实 reasoning 绑定。

## 固定批次与停止条件

保留 20-task 试跑、200-task 独立验证包，以及所有 3220 个计划槽位及 seed。正式批次沿用 expand800 → 1200 → 1600 → 2000 → 2400 → 2800 → 3000 的累计配额；完成整批四次采样后检查唯一合格轨迹数，最早在 1600-task 批次交付。不得靠重复行、改名或教师失败后降低难题配额达到目标。

至少 3000 条唯一合格轨迹、当前批次完整、所有审核与格式验证通过后，发布 `training-handoff.json` 并等待外部 SFT 与评测。未决证据仍标记不完整，不伪造成功或外部评测通过。
