# 原生银行定向合成与训练交付

本版落实 2026-09-18 确认的退化修复路线：保留逐轮画像、冻结配额、双模型审核和固定四次采样，业务后端使用真实 `banking_knowledge` 数据结构、工具签名、政策与 `bm25_grep`。旧 V2 轮次、SFT 文件和官方任务不改写。实际推理设置按用户确认视为一致，不以 `reasoning_effort` 的日志差异解释退化。

## 阶段和配额

独立新轮次执行：报告分析 → 冻结 3000 个训练槽位及 200 个额外验证槽位 → 20 题试跑 → 前 400 题训练包 → 外部训练及配对测评 → 扩至 3000。验证任务按业务图的哈希组与训练隔离；试跑不混入正式 SFT。官方 97 题是适应性开发反馈，不能称为独立留出集。

| 业务族 | 前 400 题 | 完整 3000 题 |
|---|---:|---:|
| 争议和返现 | 100 | 750 |
| 借记卡处理 | 80 | 600 |
| 账户和资金依赖 | 60 | 450 |
| 产品、推荐及利息计算 | 60 | 450 |
| 核验和精确参数 | 40 | 300 |
| 用户实际执行 | 40 | 300 |
| 升级和知识边界 | 20 | 150 |

难度边际为 15/25/25/20/15%，对应参考动作数 1–4/5–9/10–14/15–19/20–29；同时记录真实业务写入数。分配器用已支持的业务与难度组合保持两个边际，不根据教师成功率调低难题比例。来源标记为 70% 当前缺口、20% 原生能力保持、10% 原生组合探索；本版不回灌旧案例更新轨迹。

生成器先创建新客户、账户、卡、交易、资金和业务义务，再由 GLM 改写开场。覆盖多交易争议、正确交易干扰项、冻结/PIN/关卡补卡、安全限制、临时限额 60 天及 150% 边界、开户/清空关户、移动存款后转账、个人卡净收益、推荐总收益、全年利息的档位与叠加收益、分情形转人工。此目录不是官方全部业务的完备实现，未注册业务不得由 LLM 自行编造。

补卡必须区分账户档位：Light Blue（Entry）当天关卡后需等待 48 小时；其他已支持档位可以立即补卡。独立检查器拒绝“工具调用成功但违反等待期”的参考流程，并验证提前补卡负例。试跑发现的旧错误候选保留在原版本，按同一槽位最多三次的内容重建预算修复，不将正确等待判成教师遗漏。

## 运行

配置为 `configs/synthesis/targeted-native-v2.yaml`。GLM 教师、生成和分析；Gemini 用户及质量审核；两者分别公开盲解及独立审查。端点为 `http://10.39.62.231:9091/v1`，所有角色共用物理请求池，上限 **256**。池快照与 `budget.json.by_model/by_stage` 给出实际调用分布；并发上限不等于每时每刻有 256 个在途请求。

```bash
.venv/bin/python scripts/run_targeted_native.py \
  --round-dir data/synthesis/targeted-native-20260918 \
  --config configs/synthesis/targeted-native-v2.yaml \
  --report docs/tau3-banking-sft-regression-improvement-plan-20260917.md \
  --run data/simulations/tau3_banking_dots3-note-oi-stage2_1trial \
  --round-id native-regression-20260918 \
  --base-model dots3-pre-sft-d3note
```

独立入口仍是 `tau3 synthesize targeted analyze/plan/pilot/generate/collect/export/report`。使用 `--stage small` 或 `--stage full`；额外验证集用 `generate --split validation`。相同输入续跑加 `--resume`。后台驱动依次交付前 400 题和验证 bundle 后，明确停在 `WAITING_EXTERNAL_EVALUATION`，不会自行训练或跳过扩量门槛。

报告按原文段落分块抽取，显式给出 F1–F8/F3b 定义；只有已注册机制可进入规划。缺乏证据的业务族单独分析相关原文，仍无依据则报缺口。引用仅允许可追溯的排版引号规范化，未知分类进入 `analysis-backlog.json`，不补造统计。实际网关的完整报告请求曾耗尽 16384 输出 token 且没有最终 JSON，设置低 reasoning effort 也未解决；已改为有界分块，保留原失败请求及费用。

结构化审核对两模型均请求低 reasoning effort，教师和用户对话配置独立保留；该设置是请求参数，实际是否生效以网关响应为准。Gemini 在高、低 reasoning 请求下均出现过用完 16384 token 而没有最终 JSON，因此其结构化审核单独配置 32768 输出 token 和 900 秒上限；不能把空响应算作拒绝或通过。双模型盲解预算覆盖内容重建上限（最多 19320 次），同时仍受物理请求、审核调用和 token 总预算约束，教师正式预算仍为 12000 次。

每个正式有效任务固定四个 seed，GLM temperature=0.7，用户/审核为 0，200 步、1800 秒。一次逻辑轨迹的截止时间跨恢复保留；停机时间也计入其墙钟预算。逐个物理响应落盘，已完成前缀从原响应恢复，结果不明的请求不换 seed 重发。截断、基础设施异常和审核未决保留为不完整证据；内容有确凿错误的候选最多重建三次，盲解失败不自动删题。

公开盲解若已保存完整采样证据、正常触达步数/时间/工具错误上限，保留其未完成和失败状态，继续由该模型独立审核任务公开可解性；准入不要求两个求解器都解出题。传输结果不明、缺失捕获和基础设施异常仍阻塞准入。教师四次采样对超时、截断的“不完整”口径保持不变。

## 产物和验证

- `snapshot/`：实际公共 DB、文档、运行时代码字节与工具 schema；不包含官方 golden 或凭据。
- `profile.json`、`plan.json`、`plan-binding.json`：来源证据和冻结配额。
- `tasks/{pilot,train,validation}/`：新业务实例、正负例、两模型盲解与审查、四次轨迹、质量结果、单槽位 SFT 分片。
- `pilot/`、`small/`、`full/`：完整分母统计、环境成功数和合格样本数各自的 0–4 分布、难题池、`sft.jsonl`、`general_agent_reasoning.jsonl`、`training_manifest.json`。
- `validation/bundle/`：200 题外部测评包，加载时检查任务、分组、运行时和公共语料哈希。
- `physical_calls/`、`budget.json`、`llm_pool/`、`supervisor.json`：物理请求、累计预算、实际在途并发及阶段状态。

准入验证真实官方参考执行和独立业务目标，拒绝空操作、漏对象、错误金额/选项、重复入账、额外写入和工具全部可执行但安全路径错误的反例。额外合法查询可接受。用户交接必须看到真实用户调用及成功结果。利息调查工具在当前官方 DB 中没有独立持久表，因此其义务按真实成功调用及“补款在报告之前”检查，不能声称已经验证后台工单持久化。

全部合格成功轨迹保留；语义错误 reasoning 拒绝整条，局部错误工具动作屏蔽整个 assistant 回合，但保留上下文。导出重新绑定实际成功捕获、审核和准入证明，拒绝改动后的分片。每题 k 条样本的权重为 1/k。训练端必须实际使用该权重或等价的按 task 均匀采样，不能直接把 JSONL 行数当成训练曝光比例。

运行时代码修复会产生新快照。若仅修复对话完成后的判分接口，可在逐文件证明公共环境、提示、候选、模型配置及 seed 均未变化后，导入已完成的原始捕获并重新判分；原捕获、哈希、来源版本和累计预算必须保留。未完成或传输结果不明的请求不能借此获得新采样机会。通常恢复仍须使用同一版本与 `--resume`。

训练参考为用户提供的 `/cpfs/user/liujialong/model/tau3.v0.2/iter_0000074_hf_fp8_infra`，仅用本地 tokenizer 和模板，不加载权重。参考适配器为 `tau3.synthesis.targeted.native.training.encode_sample`：保留原始 reasoning、外层工具对象和内层 JSON 字符串，保留所有工具结果，只有未屏蔽 assistant 内容产生 labels。本轮训练契约最大长度 131072；超过时完整保留原始成功捕获，逐条标记 `REJECTED_LENGTH`、不进入训练 JSONL，任务与四个槽位保留，不截断、不重采。模型文件的 `max_position_embeddings=393216` 不代表外部训练加载器已经配置了该长度。格式或 mask 验证错误则标记未决，不能当作普通长度拒绝。分段渲染必须与完整实际模板逐字一致，并检查工具参数往返。这个检查不能替代尚未提供的外部训练加载器和服务解析器验证。

## 外部训练回执与扩量

`tau3 synthesize targeted accept-evaluation --receipt receipt.json` 接收：

- `training`：`base_checkpoint`、`candidate_checkpoint`、`data_manifest_hash`（READY 训练清单的规范 JSON SHA256）、`tokenizer_hashes`、`chat_template_hash`、`adapter_hash`、`max_length`、`hyperparameters`、`mask_verified`。
- `official`、`validation`：各自的 `task_ids`、`baseline_dir`、`candidate_dir`，均为现有 runner 保存的 `results.json` 与 `simulations/*.json` 目录。

导入器读取实际文件核对任务内容、有效推理设置和相同的五个 seed；不信任手填的“提升通过”布尔值，也不使用可能过期的 simulation_index。两套各需提升至少 3 个百分点且按 task 配对 bootstrap 的 95% 下界大于 0；官方 5–9 步桶不能下降，原 4/5 以上保护任务总体下降不超过 5 个百分点且单题不能掉至 2/5；不存在工具和额外成功写入的 task 比例不得升高。诊断由调用、结果和真实工具元数据重算，正式分数仍按原 reward。门槛不通过时停止扩量并保留证据。

### 2026-09-18 传输与审核恢复修订

`recover_targeted_native_transport.py` 为已停止的原生轮次建立新的实现版本，保留旧轮次作为证据。该恢复不更换任务、四个 seed、教师参数或配额；物理请求和 token 预算累积继承，已有成功轨迹及合格样本复用。

- 结构化审核最多三个独立请求，始终严格解析完整 JSON。重试重新审核原始输入，不修补或猜测判决；每次原始响应单独保存，恢复不会刷新重试上限。
- 用户模拟器空响应及已确认的超时/连接错误允许最多三次物理请求。用户空响应重试增加通用的非空输出提醒，所有请求均计费留档。未确认的在途请求、截断的教师输出和空教师输出仍保持未决，不重新抽样。
- 完成的消息从响应日志回放，恢复沿用原 seed。仅针对已确认停止的基础设施异常，修复版本显式排除离线停机时间，扣除此前完整可观察执行区间；剩余时间只授予一次，并绑定原采样身份。此恢复会记录在 `lineage.json` 和槽位的 `clock-recovery.json`，不得解读为原始墙钟预算内无中断完成。
- 质量审核未决时，已经验证的环境成功仍保留；SFT 资格继续为未决。试跑必须满足 20 个有效任务和 80 个完整槽位才会放行正式阶段。

恢复命令：

```bash
python scripts/recover_targeted_native_transport.py \
  --parent data/synthesis/targeted-native-20260918-r6 \
  --round-dir data/synthesis/targeted-native-20260918-r7
```

后续真实回放还发现 `KB_search` 输出包含非确定性的毫秒耗时尾注。原生恢复适配器会重新执行查询，并逐字比较去除该固定格式尾注后的内容；工具名、参数、文档内容任一变化仍拒绝恢复。仅当差异限于该尾注时，才恢复此前实际返回的完整文本，保证模型请求与原始历史一致。每次恢复记录在槽位的 `retrieval-replay/`；官方工具和检索行为本身不修改。该检查已在原未决长轨迹上离线验证到原超时请求的位置，全程没有发起 LLM 调用。

### 正式首批恢复（r9）

首批 r8 的 632 条合格样本已使用其原始冻结运行时完成导出。后续恢复继续在独立的 `frozen-runtime` 中执行，避免其他域或控制台开发触发快照漂移；不修改或绕过原始快照检查。

r9 是显式的预算扩展实验：每条轨迹总时间上限从 1800 秒增至 3600 秒，固定 seed、200 步限制和教师参数保持不变。已有完整轨迹复用；未完成轨迹从日志回放后继续，并扣除之前的实际执行区间。旧的超时结果保存在父轮次及 `pre-extension-*` 记录中。r9 的结果不能当作原 1800 秒预算下的 pass@4。

恢复后的两个端点均先进行了计费探测。已有后端鉴权/配额异常请求按明确的 physical ID 授权恢复，新增网关瞬态错误按配置有界重试；每个消息位置至多保留三次物理尝试。所有失败与重试继续累计预算。审核结果增加 Pydantic schema 和 assistant 索引范围验证，错误输出重新审核原始证据，不修补判决。

补卡准入审核额外提供已在公开知识库中的账户档位映射文档 `doc_bank_accounts_bank_accounts_(general)_005`。三次改写均失败的 00190 槽位保留原始业务实例，恢复与源请求逐字相同的表述，并仍须通过独立盲解与双模型准入；被拒改写记录不删除。

试跑预算测量单独冻结，恢复时不把正式生成/采样成本误算为试跑开销。正式导出存在未决缺口时保留 `INCOMPLETE` 状态，并继续执行独立验证任务生成，避免已授权的后续工作被部分数据导出状态阻断。

为避免恢复时重建十余万个小文件，新轮次的 `evidence-parent.json` 绑定父轮次快照，只读引用其物理请求记录。新请求写入新轮次目录；旧记录不移动、不覆盖。已完整结束的轨迹只复用捕获、结果和审核证据，不复制无需再次回放的请求日志。因此恢复轮次依赖父轮次证据目录，归档时必须同时保留父链。
