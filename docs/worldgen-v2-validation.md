# Worldgen V2 实施与验证记录

日期：2026-09-12。操作范围：在现有 worldgen 上增加 V2 生成、执行、验证和发布链路，并保留旧产物用于开发排查。本文记录实际观察，区分内部正确性、模型审核和论文效果复现。

后续验收边界：本文记录的是基础版本历史证据。答案可见的任务审核不属于盲解验证；模拟评分器的反例测试不属于真实模型校准。下一阶段的独立验证和扩展准入见 [独立验证说明](worldgen-v2-independent-validation.md)。

## 主要修改

| 原风险 | 本次修改 | 验证证据 |
| --- | --- | --- |
| 选品任务硬编码 checking、卡产品误路由 | V2 按品类契约分发表和操作；旧生成器不再静默把卡当 checking | 品类归属、错误产品与客户反例；8 个起始品类完整构造 |
| 无状态变化就可能误得满分 | 独立环境目标 + 必要的语义断言；V2 拒绝省略奖励分量的评分模式 | 错误知识边界回答在完整 evaluator 中得到 0 分；空／漏判／非布尔判定不通过 |
| 文档模板覆盖布尔否定、漏活动窗口 | 从结构化事实和表达式编译主张，保留否定、日期、推导公式 | 日期边界和派生依赖测试；最终正文与主张一致性检查 |
| gold 漏依赖、只证明参考答案 | 传递闭包包含日期、规则参数、操作事实和竞争者，确定性地裁剪冗余 | 反转文档读取顺序结果不变；逐文档删除检查 |
| 参考流程可执行但任务描述可能错误 | 精确匹配受测 scaffold，否则必须进行双模型任务语义准入 | 篡改请求但保留目标会被阻止；新取消品类双审通过 |
| 不适用的规则混入同一文档 | 规则明确列出适用工具；工具明确列出自身规则 | 真实 Gemini rollout 曾误把开户年限用于提款，修复后同类提款成功 |
| 品类复制产生隐藏选品歧义 | 唯一的用户可见品类范围，并明确写入选品请求 | 多品类复制与重复范围拒绝测试 |
| 数量增长被当作多样性增长 | 从状态变化、角色、规则和流程计算结构指纹；按结构分组切分 | 12→24 品类仍计为 12 种结构；新取消流程增加第 8 种结构 |
| 任意旧 published 标志／缓存结果被信任 | 精确产物、实现、报告及运行配置身份；失败／陈旧内容拒绝发布和复用 | 文档、任务、DB、spec、配置修改均使旧证书失效 |

## 最终离线检查

执行：

```bash
uv run pytest tests/test_domains/test_banking_knowledge/test_worldgen*.py \
  tests/test_runner \
  tests/test_domains/test_banking_knowledge/test_tools_knowledge.py \
  -q --disable-warnings --maxfail=3 --tb=short
```

结果：**428 passed**。覆盖 worldgen、runner 和官方 banking 工具。变更文件的 Ruff 检查、格式检查和 `git diff --check` 也已执行。

另一次包含旧 `tests/test_run.py` 的在线检查有 3 项失败，原因是测试硬编码的 `gpt-3.5-turbo` 未被当前 API key 授权，返回 HTTP 403。该失败没有记为通过，也没有为了通过测试更改官方模型默认值。V2 rollout 已使用用户指定的两个网关模型。

## 自动横向扩展实测

Gemini 自动提出一个不同于初始 profile 的“预约转账取消”品类：一个产品、一张表、客户授权与助手取消两个操作，一个顺序任务。随后 Gemini 和 GLM 分别检查请求、目标、输入、沟通断言及状态规则，两者均通过。

该候选经过最终实现重新审核、执行验证并发布到 `data/synthetic/worldgen-v2-final-expanded/`：**5 品类、13 产品、68 文档、21 任务、8 种结构**。原 4 品类世界为 7 种结构；因此这次扩展增加了实际流程结构，而非仅修改名字。

候选及初次审核记录位于 `data/synthetic/worldgen-v2-proposal-verified/`；最终世界保留当前代码下的复核、扩展来源和验证结果。这个例子证明了无需人工校对即可完成一次新品类提出与准入，不代表任意提出的品类都会成功。

## 文档双审与在线 rollout

网关：`http://10.39.62.231:9091/v1`。已读取 `/v1/models`，实际模型 ID 为 `gemini-3.5-flash` 与 `GLM-5.3-Flash`。完整配置见 `configs/worldgen/v2-rollout.yaml`：两个智能体模型对照，用户模拟器用 Gemini，语义评分用 GLM。

单篇自然语言改写与双模型复核曾通过，记录位于 `data/synthetic/worldgen-v2-review-smoke.json`。完整单品类双审在迭代期间预留了 75 次模型调用，接受 6 篇文档后，因输出截断及后端配额／鉴权错误停止。`worldgen-v2-reviewed-smoke` 保持 draft／`INCONCLUSIVE`，没有发布为通过语料。这些记录只说明复核链路被真实调用，不是最终自然语言语料质量的认证。

随后使用经过执行检查和答案可见双模型审核的新取消品类完成了一个较小的全流程自然语言样本，发布目录为 `data/synthetic/worldgen-v2-final-natural/`：**1 品类、1 产品、4 篇自然语言文档、1 个顺序任务**。Gemini 完成改写，Gemini／GLM 对任务分别审核，并对每篇最终文档各自进行全文主张抽取与复核；不通过的草稿在限定次数内自动修复。最终全部通过执行、证据和反例检查，证书范围为 `structural_and_model_reviewed_text`。共预留 37 次模型调用，全程未人工改稿。这证明该闭环有完整成功实例，仍不能推导大规模语料的误差率。

首次 2 任务 × 2 模型 rollout 记录在 `worldgen-v2-rollout-smoke`，用于发现规则适用范围问题；其中 GLM 有基础设施失败。修复后的最终回放记录在 `data/synthetic/worldgen-v2-final-rollout/`：在 `golden_retrieval`、1 次 trial、最多 30 步条件下，Gemini **2/2 成功**，GLM **2/2 成功**。此前 Gemini 误用开户规则而拒绝提款的情况已消失。

这是小样本执行验证，不是统计等价证据；每侧只有 2 个任务，报告中成功率的 Wilson 95% 区间仍约为 `[0.342, 1.0]`。运行是否完整、任务成功率和统计等价是不同指标，不能把完整运行的 `PASS` 当成所有任务都成功。

## 仍不能宣称的结论

- 尚未完成“两个智能体 × 至少三种检索条件 × 每侧至少 50 个任务”的完整官方对照，因此论文难度接近仍为 `INCONCLUSIVE`；不能以小样本通过率代替该实验。
- 双模型审核降低风险，不能保证不发生共同误判。受控文本的自然度和模板多样性也不等同于论文语料。
- 起始品类是明确边界的虚构银行例子，不是现实银行产品／法规的复刻；初始记录是合成快照，不伪装为真实交易历史。
- 当前声明式操作支持品类内多表联动，任意跨品类业务交互、完整复式总账和历史事件生成尚不在此实现的保证范围内。复杂业务可先建模为复合品类，但仍必须经过准入验证。

完整使用说明、模型配置、证书条件及持续扩展命令见 [Worldgen V2](worldgen-v2.md)。
